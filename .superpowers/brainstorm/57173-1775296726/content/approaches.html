Three Architecture Approaches

Each handles state, routing, and real-time differently — pick the one that matches how you'll use this tool

A

Lightweight — React + Context

Single page, no routing. Case threads live in React context (in-memory). Selecting a case swaps the chat panel. SSE connection opens per case on selection.

Pros

  • Minimal setup, fast to build
  • No extra dependencies
  • Simple mental model

Cons

  • Conversations reset on page refresh
  • Can't deep-link to a case

Best if: this is an internal tool, sessions are short, and you don't need bookmarkable URLs

B

Persistent — React + Zustand + localStorage

Single page with state manager (Zustand). Message history persists in localStorage per case ID. SSE reconnects automatically and replays missed messages via a sequence ID.

Pros

  • Conversations survive refresh
  • Reviewer can pick up where they left off
  • Lightweight (Zustand is tiny)

Cons

  • Still no deep-linkable URLs
  • localStorage has size limits for long threads

Best if: reviewers work multiple cases over hours and need session continuity

C

Routed — React Router + Zustand

Each case gets its own URL (/case/C-7891). React Router handles navigation. Zustand manages state. Deep-linkable, browser-history-aware.

Pros

  • Share/bookmark specific case chats
  • Browser back/forward works naturally
  • Cleanest for multi-reviewer teams

Cons

  • More setup (router config, URL params)
  • Slightly more complexity

Best if: multiple reviewers might share links or this integrates with other internal tools

My recommendation

B (Persistent) — For a case review tool, losing conversation history on refresh is painful. Zustand + localStorage solves that with minimal overhead. If you later need routing, it's easy to add React Router on top.
